How Saakshi is built

Technology architecture: the parts, the tools we chose, how it stays safe and how it scales.
Big idea: the seat signs every answer, and nothing in the middle is trusted. Each part only has to be checked, never believed.

The whole system on one page

The data flow, step by step

1The candidate taps an answer. The seat signs it and saves it to disk.
2The seat sends it over the local network to the centre relay.
3The relay checks the signature and the chain, then sends a copy to the cells.
4A cell unlocks the answer, checks it and signs a receipt back.
5Control seals each shift into one fingerprint. The witness checks it.

One answer, three ticks

Like a chat app, the candidate sees how far the answer has travelled. Each tick needs a real check, not a promise.

TickWhat it meansIf it fails here
✓Signed and saved on the seat's own diskNothing is lost except the last few seconds. The candidate moves to another seat.
✓✓The centre relay holds a checked copyThe relay buffers. Answers keep flowing when the link is back.
✓✓ blueA cell has opened, checked and signed for itSafe even if the relay or one cell is destroyed.

Technology choices

PartWhat we useWhy, in plain words
Exam app on the seatElectron, React, TypeScriptOne app for macOS and Windows. It can run offline and look at running programs on the machine.
Servers (relay, cell, control, witness)One Bun program with four modesOne thing to ship and test. Each mode is a different job.
StorageSQLite, with full sync to disk on every writeNo database server to run. An answer that was acknowledged survives a power cut.
SigningECDSA P-256 and SHA-256Standard, widely reviewed, built into the platform.
Locking answersECDH, HKDF and XChaCha20-Poly1305Only the cell can open an answer. The relay cannot.
Tamper logMerkle tree (RFC 9162)One short fingerprint proves the whole record is unchanged.
Key custodyShamir secret sharing, 2 of 3No single person can open the paper before the exam.
Risk analyticsPython with numpy, scipy, networkxStrong maths tools. Control reads the result back as plain data.
Live viewsServer-sent eventsSimple one-way live updates for control screens, and they replay what was missed.
