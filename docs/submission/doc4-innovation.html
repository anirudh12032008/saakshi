What is new in Saakshi

Most exam systems try not to fail. Saakshi assumes things will fail, and makes every failure safe, small and provable.

The big picture

Six ideas, one picture each

1. A receipt the candidate can check

The seat makes the receipt code at submit, even offline. It equals the code the cell countersigns. The candidate and the public page can compare them.

2. A signed log with an outside witness

Answers are chained, and the log is sealed. A separate witness only co-signs a log that grows from the last one it saw. In our test, a rewritten 94-entry log was refused and raised a tamper alert. 1,000 of 1,000 byte flips were located.

3. Answers never lost

Every answer is saved on the seat first, then forwarded. If a link or a cell fails, the data waits and catches up. In 20 of 20 chaos runs, 16,000 sent equalled 16,000 stored. Recovery took about 1 second.

4. An offline code start

Two of three key holders release the paper keys. A centre with no link gets a code by phone. The code works only for that centre and shift. A typo, or another centre's code, is refused. Result: 308 candidates at 7 centres started.

5. Re-test only the harmed

The cells' own records show who lost time. Only those candidates are re-tested. In the demo, 193 were re-tested and 1,190 were spared a needless re-test.

6. History only corroborates

Past records never create a flag and never change a decision. They only add a note. In the demo the flag set and the headline were unchanged, with 53 flags, 4 of them corroborated and none on an honest candidate.
