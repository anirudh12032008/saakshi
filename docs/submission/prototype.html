Saakshi — working prototype

A resilient, provable CBT exam ecosystem: every answer is signed and hash-chained at the seat, the system survives relay, cell and link failures, and any tampering afterwards is locatable and recoverable.
Repository: https://github.com/anirudh12032008/saakshi
Tested on macOS and Windows (Windows: automated CI on windows-latest, incl. end-to-end test of the packaged seat)

This document shows that Saakshi is running software, not a concept. Five scripted demo acts drive real seat, relay, cell and control processes (not mocks) and each writes an evidence file to docs/evidence/. The design never auto-penalises a candidate: flags go to a human reviewer.

Key limit, stated up front: a seat signature proves a record was not altered after the device produced it, not that the candidate chose it. All analytics figures use synthetic data and all performance figures are loopback on one host.

Architecture

  • Seat — Electron app at the exam PC; signs and hash-chains locally, fsyncs, works offline.
  • Relay — untrusted store-and-forward at the centre; sees only sealed envelopes.
  • Cell — one of three independent national-DC processes; verifies chains, countersigns, seals a per-shift Merkle register.
  • Control — signs the tree head, runs the audit, serves /verify and the evidence pack.
  • Witness — separate process that cosigns a tree head only with a valid RFC 9162 consistency proof; a rewritten register raises a P0 TAMPER incident. In the demo it shares a machine with control; independent custody is roadmap.
